Explicación General del Sistema

El sistema para la perfumería BEMA es una aplicación web cliente-servidor desarrollada con HTML, CSS, PHP y MySQL (PDO) que permite gestionar cuentas de usuario de manera segura.

Área Pública

Permite a los nuevos clientes registrarse desde un formulario. Tras iniciar sesión, acceden a su panel personal con sus datos protegidos.

Área Administrativa

Exclusiva para el rol admin. Permite listar, buscar por filtro, editar datos, archivar cuentas (borrado lógico) y reactivarlas.

Estructura de la Base de Datos (bema_perfumeria)

Se creó la base de datos y la tabla usuarios en phpMyAdmin con las restricciones obligatorias (`UNIQUE`, `DEFAULT`, `TIMESTAMP`):

CREATE DATABASE bema_perfumeria
CHARACTER SET utf8mb4
COLLATE utf8mb4_unicode_ci;
USE bema_perfumeria;
CREATE TABLE usuarios (
id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
nombre VARCHAR(80) NOT NULL,
apellido VARCHAR(80) NOT NULL,
dni VARCHAR(20) NOT NULL UNIQUE,
email VARCHAR(254) NOT NULL UNIQUE,
password_hash VARCHAR(255) NOT NULL,
rol VARCHAR(20) NOT NULL DEFAULT 'usuario',
creado_en TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
archivado_en TIMESTAMP NULL DEFAULT NULL );

Organización de Archivos en XAMPP

Los archivos están organizados en la carpeta C:\xampp\htdocs\bema_perfumeria\:

Archivo Función Principal
conexion.php Conexión segura a MySQL utilizando PDO y manejo de excepciones.
registro.php Formulario público y procesamiento de alta de nuevos clientes.
login.php Autenticación de credenciales e inicio de $_SESSION.
panel.php Panel personal protegido exclusivo para usuarios autenticados.
admin_usuarios.php Panel de administración con listado general y buscador integrado.
editar_usuario.php Formulario y actualización de datos de un usuario existente.
archivar_usuario.php Ejecuta el borrado lógico (marca fecha en archivado_en).
usuarios_archivados.php Listado de cuentas desactivadas con opción a reactivación.
reactivar_usuario.php Restaura cuentas archivadas (vuelve archivado_en a `NULL`).
cerrar_sesion.php Destruye la sesión activa de PHP de forma segura.

Medidas de Seguridad Implementadas

  • Cifrado de Contraseñas: Almacenamiento mediante password_hash() y verificación al ingresar con password_verify(). Sin texto plano.
  • Consultas Preparadas (PDO): Uso de prepare() y execute() para anular riesgos de Inyección SQL.
  • Control de Sesión y Rol: Las páginas privadas comprueban $_SESSION['usuario_id'] y el rol en el servidor antes de renderizar HTML.
  • Escapado de Salida: Filtrado de datos mostrados en pantalla con htmlspecialchars() para prevenir vulnerabilidades XSS.
  • Aislamiento de Privilegios: El rol de administrador no se puede asignar desde el formulario público.

Dificultades Encontradas y Soluciones

Dificultad 1: Error crítico al intentar registrar DNI o Mail duplicado

Solución: Se capturó la excepción de PDO mediante un bloque try/catch identificando el código de error SQLSTATE '23000'. Esto permite mostrar un mensaje amigable al usuario indicándole el duplicado sin detener la aplicación.

Dificultad 2: Protección de accesos directos por URL en páginas privadas

Solución: En el inicio de cada archivo privado se incorporó una validación que verifica la sesión y el rol. Si la verificación falla, se envía un código HTTP 403 y se detiene la ejecución del script con exit().
